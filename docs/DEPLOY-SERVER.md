# פריסת שרת המתכונים — מדריך צעד־אחר־צעד לשוקי
> Deploy guide for the Sue Chef recipe server. Written in Hebrew for the owner;
> UI labels appear in English exactly as they show on screen.
> עודכן: 30.8 — מותאם למאגר `shukinton/suechef-app` (כל הפרויקט במאגר אחד,
> השרת בתיקיית `server/` — ולכן ב־Render מוסיפים הגדרה אחת: Root Directory).

## מה הולך לקרות
שרת המתכונים (התיקייה `server/` — קיבלת אותה גם כ־`suechef-server.zip`) יעלה לאינטרנט
בחינם, יקבל כתובת קבועה משלו (למשל `https://suechef-server.onrender.com`), ואת הכתובת
הזו נדביק פעם אחת בהגדרות האפליקציה. מאותו רגע — מדביקים קישור של אינסטגרם/טיקטוק/אתר
מתכונים במסך הבית, ו־Sue מביאה את המתכון לבד.

**מה רק אתה יכול לספק** (בגלל זה זה מדריך ולא משהו שעשיתי לבד):
1. חשבון GitHub (חינם) — שם יישב הקוד.
2. חשבון Render (חינם, בלי כרטיס אשראי) — שם ירוץ השרת.

**כמה זה עולה:** 0 ₪. המסלול החינמי של Render נותן 750 שעות בחודש (מספיק לשרת אחד
שרץ כל החודש). המחיר האמיתי היחיד: אחרי 15 דקות בלי שימוש השרת "נרדם", וההתעוררות
לוקחת עד דקה — האפליקציה כבר יודעת את זה ומציגה "Waking the kitchen up…" בזמן ההמתנה.
אם יום אחד זה יציק, שדרוג ל־Starter‏ ($7 לחודש) מבטל את ההירדמות.

**למה לא Fly.io?** בתוכנית המקורית הזכרתי גם את Fly — בדקתי שוב הלילה: Fly ביטלו את
המסלול החינמי ללקוחות חדשים (נשאר רק תשלום לפי שימוש). Render הוא המסלול, והוא מספיק.

---

## שלב 1 — העלאת הקוד למאגר (5 דקות)
המאגר `github.com/shukinton/suechef-app` כבר קיים. נשאר למלא אותו:
1. חלץ את `suechef-github.zip` (שקיבלת בצ'אט) לתיקייה במחשב — ייפתחו בתוכה
   תיקיות (`app`, `server`, `docs`…) וקובץ `README.md`.
2. פתח בדפדפן את דף המאגר → **Add file** → **Upload files**.
3. פתח את התיקייה שחילצת, בחר **את כל מה שבתוכה** (Ctrl+A) וגרור אל חלון ההעלאה
   בדפדפן. GitHub יודע לקבל תיקיות שלמות בגרירה.
4. חכה שכל הקבצים ייטענו לרשימה, ואז למטה: **Commit changes**. זהו — הקוד באוויר.

## שלב 2 — חשבון Render ופריסה (10 דקות + ~5 דקות בנייה)
1. גלוש אל **render.com** → **Get Started** → הכי קל: **Sign in with GitHub**
   (זה גם מחבר את החשבונות — חוסך את שלב החיבור אחר כך). אשר את ההרשאות.
2. בלוח הבקרה: **New +** → **Web Service**.
3. תחת **Git provider** בחר את המאגר `suechef-app` (אם אינו מופיע: **Configure account**
   → תן ל־Render גישה למאגר → חזור). לחץ **Connect**.
4. בטופס ההגדרה:
   - **Name**: `suechef-server` (זה קובע את הכתובת. שים לב: הכתובות גלובליות —
     אם השם תפוס תקבל משהו כמו `suechef-server-xxxx.onrender.com`. הכתובת האמיתית
     תמיד מוצגת בראש דף השירות — העתק אותה משם).
   - **Region**: `Frankfurt (EU Central)` — הכי קרוב לישראל.
   - **Root Directory** ⬅️ חשוב! כתוב בשדה הזה: `server`
     (המאגר מכיל את כל הפרויקט; השרת גר בתיקיית server. אם אינך רואה את השדה —
     פתח את **Advanced**.)
   - **Language / Runtime**: Render מזהה לבד את ה־**Dockerfile** ובוחר Docker. אם שואלים — Docker.
   - **Instance Type**: **Free** (512 MB RAM, 0.1 CPU — מספיק לנו).
   - **Environment Variables**: לא חובה כלום — ברירות המחדל בקוד כבר נכונות
     (claude.ai + אתרי netlify.app מאושרים). אם בעתיד יהיה דומיין משלך, נוסיף כאן
     `ALLOWED_ORIGINS`.
5. **Deploy Web Service**. עכשיו סבלנות: הבנייה הראשונה מורידה דפדפן שלם (~5 דקות).
   כשמופיע **Live** ירוק — סיימנו.

## שלב 3 — בדיקה (דקה)
> ⚠️ **חשוב באיזו גרסה בודקים:** דף התצוגה של claude.ai (הארטיפקט) חסום מלפנות
> לשרתים חיצוניים — שם ייבוא קישורים *לעולם* לא יעבוד, לא משנה כמה השרת תקין
> (האפליקציה תגיד לך את זה בכנות אם תנסה). בודקים מהאפליקציה המותקנת — **הקישור
> של Netlify** בטלפון, או קובץ `suechef.html` שפתחת ישירות.
1. העתק את הכתובת מראש דף השירות ב־Render (למשל `https://suechef-server.onrender.com`).
2. פתח בדפדפן: `https://suechef-server.onrender.com/health`
   צריך להופיע: `{"ok":true,...}` — אם השרת ישן, ההמתנה הראשונה היא ההתעוררות (עד דקה).
3. עכשיו באפליקציה (הגרסה מהלילה): **Settings** → **Developer options** → הדבק את
   הכתובת בשדה **Recipe-server address** → לחץ **Test connection**.
   - ✓ ירוק "Kitchen is awake" — מושלם.
   - "Waking it up…" — נורמלי אחרי הפסקה; המתן והכפתור יתעדכן.
   - "Can't reach it" — בדוק שהכתובת מתחילה ב־`https://` ושהשלב הקודם עבד בדפדפן.
4. מסך הבית → הדבק קישור למתכון (נסה אתר מתכונים רגיל קודם, אחר כך אינסטגרם) → **Let's Cook**.

## מה לצפות, בכנות
- **אתרי מתכונים רגילים** (עם נתונים מובנים): עובדים הכי טוב — שם, זמנים, מצרכים, שלבים.
- **טיקטוק**: מהיר (ממשק רשמי), מביא את הכיתוב של הסרטון.
- **אינסטגרם**: מביא את הכיתוב הציבורי + התגובה הראשונה. פוסטים פרטיים / חסומי־התחברות
  יחזירו הודעה כנה — ואז מדביקים את הטקסט ידנית (המסלול הזה תמיד עובד).
- **מגבלת זיכרון**: דפדפן ב־512MB זה צפוף. דפי אינסטגרם כבדים עלולים להיכשל מדי פעם —
  אם זה קורה הרבה, שדרוג ל־Starter ($7) פותר. טיקטוק ואתרי מתכונים כמעט לא מרגישים את זה.
- **הירדמות**: אחרי 15 דקות שקט. הבקשה הראשונה שאחריה איטית (עד דקה) — מטופל בממשק.
- **עדכוני קוד עתידיים**: כשאמסור גרסת שרת חדשה — מעלים את הקבצים המעודכנים לאותו מאגר
  ב־GitHub (Upload files → דריסה), ו־Render פורס מחדש לבד. שום דבר מעבר.

## פתרון תקלות מהיר
| סימפטום | סיבה סבירה | פתרון |
|---|---|---|
| Build failed ב־Render | קובץ חסר במאגר | ודא ש־`index.js`, `package.json`, `Dockerfile` כולם בשורש המאגר |
| `/health` לא עונה בכלל | השרת עוד נבנה / קרס | לשונית **Logs** ב־Render — מה כתוב בסוף? |
| האפליקציה: "Couldn't read that link" על כל קישור | כתובת שגויה בהגדרות | Test connection; ודא `https://` |
| אינסטגרם תמיד "private or behind a login" | הפוסט באמת פרטי, או אינסטגרם חוסם את השרת | להדביק את הטקסט ידנית; לנסות פוסט ציבורי אחר |
| נגמרו 750 השעות | שרתים נוספים באותו חשבון | השאר רק את suechef-server פעיל |
